Webhook Inbox

Receive webhooks from any system — Stripe, HubSpot, Shopify, your own apps — verify them, store them and process them with a regular Odoo server action. No custom controller, no lost events.

🔐 Secure by default

HMAC-SHA256 signature check with constant-time comparison, optional sha256= prefix and a timestamp window that rejects replayed requests.

♻️ Idempotent

Every event is stored once, using the sender's event ID header or a SHA-256 of the body. Duplicate deliveries are acknowledged and ignored.

⚡ Fast response

The sender gets an answer in milliseconds. Processing runs in the background, so slow logic never causes timeouts or retries on the sender side.

🧩 No-code processing

Each endpoint runs a server action. In Python code, record.get_json() gives you the payload. Failures are isolated per event.

🔁 Retries with backoff

Failed events are retried after 1, 2, 4, 8… minutes up to a configurable limit, with the error kept on the event. Retry or close them from the list.

🧹 Audit & retention

Payload, filtered headers, sender IP and timings for every event. Processed events are cleaned up automatically after N days.

How it works

1. Create an endpoint

Give it a code and a secret — the module builds the URL /webhook/<code>. Choose the signature scheme and the headers your provider uses.

2. Process events with a server action

Write a few lines of Python in a server action — create partners, confirm orders, register payments.

data = record.get_json()
partner = env['res.partner'].search(
    [('email', '=', data['email'])], limit=1)
if not partner:
    env['res.partner'].create({
        'name': data['name'],
        'email': data['email'],
    })

3. Monitor and recover

See what failed and why, with the formatted payload. Errors are retried automatically; you can retry or mark events as done at any time.

Signing requests (sender side)

Any language works: compute an HMAC-SHA256 of the raw body with the shared secret and send it in the signature header.

import hashlib, hmac, json, requests

body = json.dumps({"name": "Ada Lovelace", "email": "ada@example.com"}).encode()
signature = hmac.new(b"YOUR_SECRET", body, hashlib.sha256).hexdigest()
requests.post("https://your-odoo.com/webhook/my-endpoint", data=body, headers={
    "Content-Type": "application/json",
    "X-Signature": signature,
    "X-Event-Id": "evt_0001",
})

Responses: 200 queued, 200 duplicate, 401 invalid signature or expired timestamp, 404 unknown or archived endpoint, 413 body over 2 MB.

Built for production

  • Concurrency-safe: events are locked with FOR UPDATE SKIP LOCKED, so the cron and manual processing never run the same event twice.
  • Covered by automated tests: signatures, replay window, duplicates, retries, backoff and cleanup.
  • Only depends on base. Access restricted to Settings administrators.
  • Sensitive headers (cookies, authorization) are never stored.
